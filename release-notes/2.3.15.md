VeilGrid 2.3.15 — much lower background CPU use.

A fully attached Veilid node keeps ~32 peer connections and continuous
DHT/route upkeep; in our test that cost about 23% of one CPU core while idle.
While the app is hidden and the phone is not moving, the node now parks.

- After 5 minutes hidden with no movement, the node detaches. It wakes for a
  30-second sync window about every 5 minutes to publish the current route and
  receive messages. Scheduled location sends run inside their own short window
  and park again afterwards.
- Movement above ~1.5 m/s is checked on every fix and keeps the node attached
  for the whole trip while fixes keep arriving; reopening the app wakes it
  right away.
- Trade-off: while parked, incoming updates only arrive while the node is
  briefly attached, so a contact's position can be minutes behind; fixes
  timestamped more than 5 minutes off are dropped as stale.
- Idle CPU in the same 5–7 minute measurement fell from ~23% to ~2.5% of one
  core.
- Battery diagnostics gains a per-minute VEILID line: attachment state, live
  peers, throughput, and whether the node is parked.
- The unused Veilid API log stream is disabled; nothing in the app used it.
